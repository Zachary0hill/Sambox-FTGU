Workflow builder

One feature set, one data model, three skins. Each app gets the same hub, canvas, modals and rules. Only tokens, type, shapes and copy voice change.

What every version has

Workflows hub
Stat strip, five tabs (Workflows, Templates, Runs, Approvals, Connectors), status filters, search, cards with a mini flow preview and an on/off switch.
New workflow modal
Three starts: blank with a trigger pick, from a template, or describe it to the AI agent and get drafted steps.
Canvas builder
Top to bottom flow. Trigger first, steps after, branch cards show both paths inline. Plus buttons between cards. Zoom and fit.
Step library + finder
Left panel library grouped by type. Plus opens a finder modal with search, type chips and suggestions based on the step above.
Inspector
Right panel for the selected card. Starred fields are required. Variable chips insert into the focused field. Sample output, duplicate, delete, connect app.
Test run drawer
Runs each step on sample data, live status on every card, stops at the first broken step with a jump-to-fix button. Nothing is sent.
Review and turn on
Checklist modal: trigger set, every step set up, test passed, outward steps covered by approval. Turn on stays locked until all pass.
Ask the agent
Prompt modal with starter chips. The agent drafts steps and drops them on the canvas as unchecked cards to review.

Rules the canvas enforces

  1. One trigger per workflow. Picking a new trigger replaces it.
  2. A step with an empty starred field or an unconnected app shows a fix badge and counts in the top bar.
  3. Status pills: picking the live state opens the review checklist when the workflow is not ready.
  4. Any edit clears the last test result. Turn on needs a fresh passing test.
  5. Steps that reach people outside the team carry an outward badge.

Screen flow

Every screen links to the next one in Play. Same paths in all three apps. The hub is home, the builder is the work surface, every other screen returns to one of those two.

ScreenGoes to
HubBuilder: card, Set up, Use template, New workflow. Run detail: Runs tab row, View run, failed-run alert. Approval detail: Approvals tab title, Review and edit. Connectors: Connectors tab, Manage connectors, Reconnect, alert banner. Stat cards switch tabs.
BuilderHub: back. Run detail: Runs. Settings: Settings. Trigger setup: trigger card inspector. Condition builder: branch card inspector. Approval detail: approval card inspector. Connectors: unconnected step.
Run detailHub: back. Builder: Open workflow. Connectors: fix button on the failed step.
Settings, Trigger, ConditionBuilder: close, Cancel. The Cancel label turns into Back to builder once saved. Settings also links to Connectors for an unconnected alert channel.
ConnectorsHub: back. Builder: Used by rows. Run detail or Approval detail: next-step banner after a reconnect.
Approval detailHub: back, All clear. Builder: Open workflow. Approve or reject shows a status line, then the next item.

Build contract

Ship one WorkflowBuilder component per repo with the same props and graph shape: workflow { name, status, trigger, steps[] }, step { id, kind, title, app, outward, fields[] { label, value, required } }. Brand lives in a theme token file and a copy file (agent name, status words, step library). Feature work lands in all three at once.
